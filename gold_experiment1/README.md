# Gold: Experiment 1 (Rule-First)

Gold is where the pre-registered rules from Silver are tested against earthquakes. This folder
re-runs the 23 tests and checks them against what the Rule-First report published.

## Run it
```
python3 -m pip install duckdb pandas numpy scipy
python3 silver_text_rules/pipeline/build_silver.py            # once, makes silver.duckdb
python3 gold_experiment1/pipeline/run_experiment1.py --inputs analysis/workdir
```
`--inputs` is the folder holding `big.csv`, `quakes_m65_sid.csv`, `quakes_m65_trop.csv`,
`bg_sid.csv`, `bg_trop.csv` (generated by the earlier steps; they are large and git-ignored).
Runs are separate processes, `--jobs` at a time (default: CPU cores minus one). Each run's p-values are cached under `results/cache/`, keyed by the script and input files, so re-running or raising `--seeds` only computes the new runs. Output goes to `gold_experiment1/results/`
(git-ignored): `experiment1_gold_check.csv` (one row per result) and `experiment1_gold_summary.json`
(includes SHA-256 of the inputs and of `big_test.py`).

## Why the check is a range, not an exact match
The test script removes aftershocks ("declustering") by visiting earthquakes from largest to
smallest. In this catalogue 324 of 1,709 events are exactly M6.5, so the order among equal
magnitudes is arbitrary, and it decides which neighbours get removed. The script does not fix
that order, so the result depends on the sort routine and the row order.

Finding (200 random orders): the published file is one valid outcome of the same method.
Run exactly as committed, the script reproduces the CSV in only 13 of 46 rows, yet the published
p-value lies inside the range of the random-order runs in 45 of 46 rows (R9 holdout misses by 0.0004).
The conclusion never changes: the smallest holdout p-value over all runs is 0.0188, against the
Bonferroni threshold 0.0022 (0.05 / 23), so no rule passes in any run. Individual p-values can move
a lot, e.g. R2 sid holdout from about 0.02 to 0.06.

## What is checked
Hard (the run fails if broken): Silver's published p-values equal the committed CSV (rounded to
3 decimals); every run gives the same pass/fail verdict at 0.0022 as the published one; every run
has the same event counts per set as the CSV.
Soft (reported only): the published p-value lies inside the range of the runs.

`analysis/.../big_test.py` is never edited. The runner patches one line in a temporary copy, and
stops if that line is no longer present exactly once.
